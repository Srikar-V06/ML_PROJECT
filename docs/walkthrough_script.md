# Four-minute walkthrough

**0:00–0:45 | Start with the population.** Open artifacts/tables/population.json. We began with 2,260,668 actual Lending Club loans. The tape also contains 33 footer lines. The loan identifiers pass uniqueness checks; the member identifiers are empty. That distinction matters whenever someone asks how many individual people the model has seen. Now open artifacts/plots/censoring_by_vintage.png. The horizontal line is the 90% resolution requirement for the shorter term. The last qualifying quarter is 2016Q1. The longer loans are still resolving, so every number that follows describes an accepted, resolved cohort.

**0:45–1:25 | Trace a row into its partition.** In src/data/prep_lending_club.py, the first pass establishes eligibility and status counts on the full tape. Then the sampler selects 200,000 loans from 938,540. The second pass retrieves their fields. Open the representativeness table and point to the largest PSI, 0.0000643. Then open splits/manifest.json. The 140,000 Train, 30,000 Val and 30,000 Test loans are ordered by issue month and ID. Four expanding folds live entirely inside Train. The loader checks the sample and each membership file against their hashes.

**1:25–2:05 | Demonstrate the feature boundary.** In artifacts/feature_audit.csv, filter decision to keep. There are 99 features, including sparse origination attributes. Now show artifacts/plots/leakage_comparison.png. In the deliberately contaminated comparison, later payments and recoveries push validation AUC to 0.9996. With the audited features it is 0.7370. Open the missingness table. For each field we give the rate, likely source of missing values, and how P2 could handle it in a linear or tree model. Fold-specific transformations still have to be learned on the training fold.

**2:05–2:50 | Compare risk estimates.** Open artifacts/tables/model_metrics.csv and focus on Test. The full logistic baseline has AUC 0.7420 and Brier 0.1431. The scorecard gives AUC 0.7319. Its 30 selected features contribute additive points. Start at the base row in credit_scorecard_points.csv and add the bin contribution for each feature. Twenty more points double good-to-bad odds. Open the calibration plot to distinguish ordering borrowers from accurately estimating event probabilities.

**2:50–3:25 | Price the decision.** Show the Head of Risk memo. We set thresholds on Validation and apply the same thresholds on Test. At 10:1, the selected policy approves 30.0% and incurs 697.0 units per thousand applications. The unit is the opportunity cost of rejecting one repaying borrower. This analysis does not contain institution-specific loss amounts. The cost curve shows how sensitive each rule is to the chosen threshold.

**3:25–4:00 | Hand over the interface.** Open tests/test_models.py and the CI workflow. The 500-row offline fixture runs through the same fitting and evaluation interfaces, including a compact memorization test. The production run separately checks 1,000 real Train loans. Finally open HANDOFF.md. P2 registers a factory, tunes in the expanding folds and uses the standard CLI. Predictions carry the same loan IDs for paired inference. The external preparation delivers 55,071 aligned Prosper loans and a documented mapping for 17 features. Those definitions are the starting point for a separate transfer study.
